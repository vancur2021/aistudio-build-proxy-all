# AI Studio Build Proxy All

这是一个基于 Golang 和 Python (Camoufox/Playwright) 构建的高可用 API 代理和负载均衡系统，主要用于绕过限制并代理请求（如 Google Gemini 等 AI 服务）。

## 核心架构：主备模式 (Active-Standby) 与全局轮询池

为了在保证极低请求延迟的同时最大化节省服务器资源，系统采用了**“1主1备”**的高可用架构：

1. **自动调度**：系统启动时，会自动从 `cookies` 目录中读取所有可用的 Cookie 文件，并拉起前 2 个节点。
   - **主节点 (Active)**：负责处理所有进来的 HTTP 代理流量。
   - **备用节点 (Standby)**：在后台启动并连接 WebSocket，处于待命状态，不接收任何流量。
   - **全局轮询池**：剩余的 Cookie 会被放入一个全局队列中等待调度。

2. **透明重试与 429 拦截**：
   - 当主节点因为触发了目标 API 的速率限制（返回 HTTP 429 状态码）时，Golang 代理层会**拦截**该错误，不会将其返回给客户端。
   - 系统会立刻将缓存的请求 Body 重新发送给**备用节点**，实现用户完全无感知的透明重试。

3. **无缝切换与自愈 (Self-healing)**：
   - 触发 429 后，系统会自动将备用节点晋升为新的主节点。
   - 旧的主节点进程会被自动 Kill 掉以释放内存。
   - 系统会从全局轮询池中取出下一个 Cookie，在后台异步启动为新的备用节点。
   - 如果某个节点因为 OOM 或网络问题意外崩溃，系统也能自动感知并触发替补逻辑。

4. **Cookie 自动保活与持久化 (Auto-Renewal)**：
   - 浏览器实例在后台保持活跃时，Google 会定期下发新的、有效期更长的 Auth Cookie。
   - 系统会**精准过滤**并提取这些核心 Cookie，定期（默认每小时）将其**自动持久化**覆盖回原始的 JSON 文件中。
   - 即使容器重启或节点被调度销毁，下次启动时依然能读取到最新的 Cookie，极大延长了账号的存活周期。

## 模块说明

*   **`golang/`**: 核心代理服务。负责 HTTP 接收、WebSocket 隧道、进程管理 (`ProcessManager`)、主备状态机 (`NodeController`) 以及前端大盘 API。
*   **`camoufox-py/`**: Python 浏览器实例。使用反指纹浏览器 Camoufox 自动登录并保持页面活跃（拟人化滑动防封）。
*   **`websocket-proxy-logger/`**: 运行在浏览器环境中的前端代理客户端，负责在真实浏览器环境中发起 `fetch` 请求并将结果通过 WebSocket 传回。

## 部署与运行

本项目推荐使用 Docker Compose 进行一键部署。

```bash
docker compose up -d --build
```

*   **代理端口**: `5345`
*   **管理大盘**: `http://localhost:5345/admin`

## 节点管理控制台 (Admin Panel)

访问 `http://localhost:5345/admin` 可以打开可视化的节点管理大盘。

*   **自动调度**：您只需要通过界面上传 JSON 格式的 Cookie 文件，系统会自动接管节点的启动和主备调度。**无需手动点击启动**。
*   **角色展示**：界面上会清晰地标注当前哪个节点是“主节点”（绿色边框），哪个是“备用节点”（蓝色边框）。
*   **状态监控**：可以实时查看节点的连接状态、是否触发了 429 限制，以及获取节点的实时屏幕快照。
*   **Cookie 失效提醒**：当系统检测到某个节点的 Cookie 彻底过期（如被 Google 强制登出）时，卡片会显示醒目的红色 **“Cookie失效”** 徽章。此时您只需重新导出该账号的 Cookie 并**同名覆盖上传**，系统会自动清除失效标记并重新调度。
*   **手动干预**：如果发现某个节点卡死，您可以手动点击“停止”或“删除”，系统会自动从池子中拉起新节点进行替补。

## 环境变量配置

在 `docker-compose.yml` 中，您可以配置以下环境变量：

*   `AUTH_API_KEY`: 设置您最终对外提供服务的 API 密钥，用于保护您的代理接口不被滥用。
